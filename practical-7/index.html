슬라이드는 교실 TV에서 바로 열리고, 학습지는 A4로 인쇄되고, 앱은 태블릿 브라우저에서 그대로 돕니다. 설치할 것 없습니다.

먼저 읽어 주세요 이 단원은 코딩을 가르치지 않습니다

블록을 조립하는 기능은 외부 강사 코딩 수업이 맡습니다. 교실에서 남길 것은 「과정을 잘 짜야 결과가 나온다」 하나입니다.

그래서 앱이 교과서 116쪽의 문제 이해 → 설계 → 프로그래밍 → 실행·점검 네 화면으로 되어 있습니다. 설계를 건너뛰면 조립소가 열리지 않고, 틀린 설계는 그대로 통과시켜 실행에서 실패하게 둡니다.

1차시 컴퓨터로 문제를 푼다는 것 슬라이드 15장
교과서 108~113쪽. 교과서 밖 이야기가 절반을 넘습니다 — computer 가 원래 사람의 직업 이름이던 시절(연필로 계산하던 NASA 의 computer 들), 컴퓨터가 절대 못 하는 것(무엇을 어떤 순서로 할지 정하기), 흐린 목표와 또렷한 목표(「교실을 깨끗하게」는 로봇이 못 알아듣습니다), 라면 끓이기로 보는 어디까지 쪼개나.
도해는 전부 파일 안에서 직접 그린 SVG · 사진 파일 0개
2차시 알고리즘 — 순서를 남에게 전하는 법 슬라이드 12장
교과서 114~115쪽. 「알고리즘」은 1200년 전 사람의 이름입니다(알콰리즈미 → algorithm, 그의 책 제목에서 algebra). 자연어·의사 코드·순서도를 나란히 놓고 왜 표현법이 셋이나 있는지(읽는 사람이 다르다) 봅니다. 그리고 오늘 반드시 겪을 일 — 「오른쪽으로 돌아」가 누구 기준인가.
로봇 놀이는 화면 없이 종이로 합니다 — 아래 학습지와 짝
2차시 학습지 로봇과 프로그래머 놀이 — 명령어 적기 A4 1장 · 모둠에 1장
시작 전에 셋을 못 박게 해 두었습니다 — 한 걸음은 몇 발짝인가, 「오른쪽」은 누구 기준인가, 「돈다」는 몇 도인가. 안 정하고 시작하면 거의 반드시 엉뚱한 데로 가는데, 그게 그 시간의 알맹이입니다. 명령 12칸과 「몇 번째에서 어긋났나 · 왜(빠짐/흐림/순서)」 기록칸.
칸 격자는 전부 SVG 선 — 인쇄해도 세로선이 사라지지 않습니다
3·4·6차시 순서 설계실 (앱) 태블릿 · 학생용
이 단원의 본체입니다. 문제 이해 → 설계 → 프로그래밍 → 실행·점검 네 화면.
격자 무대(배달 로봇) 미션 1~5 — 순차·반복·선택. 문답 무대(문구점 거스름돈) 미션 6~8 — 묻고 기다리기·변수·조건. 그리고 평가 모드.
블록 이름은 엔트리 문구 그대로이고, 조작은 드래그가 아니라 탭이 본체입니다. 인터넷이 끊겨도 끝까지 됩니다(제출만 밀립니다).
미션마다 빼먹으면 실패하는 단계가 하나씩 심어져 있습니다 · 통과해도 앱이 다른 답으로 몰래 두 번 더 돌려 봅니다
5차시 평가 ① 모둠 설계 (종이) A4 2장
교과서 122~123쪽 재활용품 분리배출. 1쪽은 모둠에 1장(문제 상황·현재/목표 상태· 조각 나누기), 2쪽은 1인 1장(내 조각 설계).
2쪽의 여섯 칸은 앱 ①화면과 이름이 같습니다 — 다음 시간에 이 종이를 보고 태블릿에 그대로 옮겨 적습니다.
⚠ 모둠 설계를 태블릿으로 하지 마세요 — 넷이 하나를 서로 뺏습니다. 종이라야 동시에 봅니다
